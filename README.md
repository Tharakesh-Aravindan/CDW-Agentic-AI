# Circular Economy in Construction Waste Management and Policy Recommendation using Agentic AI

**Authors:** Tharakesh Aravindan Suresh Thanuja · Suman Neupane

This practicum builds a governed, multi-agent AI system that ingests Irish construction & demolition waste (CDW) data, computes EU Waste Framework Directive KPIs, monitors facility-level compliance, and (in later phases) forecasts waste flows, evaluates policy scenarios, and drafts policy briefs — all under a human-in-the-loop governance framework. The data pipeline unifies five years of EPA facility-level waste returns (2021–2025), CSO national waste statistics (2004–2020), Irish policy instruments, and Eurostat EU-wide benchmarks into a single analytical layer the agents consume.

## Code

### `cdw_pipeline.py` — Data Foundation & KPIs

The data pipeline that must run first. It:

1. **Loads and unifies** the five EPA Excel files (2021–2025) into a single DataFrame (≈38,900 rows total, ≈4,955 CDW rows after filtering to LoW Chapter 17).
2. **Classifies treatment codes** against the EU Waste Framework Directive hierarchy: R1 → energy recovery, R2–R11 → recycling/reuse, R12–R13 → prep/storage (excluded from final recovery), D-codes → disposal (landfill, incineration, other).
3. **Loads CSO data** (`waste.csv`, `waste_treated.csv`) and extracts the NACE F (Construction) national waste generation series 2004–2020.
4. **Computes KPIs**: annual CDW recovery rate (EU WFD-style: recovery ÷ (recovery + disposal)), top CDW material streams, and a per-licensee per-year compliance scorecard.
5. **Writes outputs** to `./out/`: `cdw_clean.parquet`, `kpi_recovery_rate.csv`, `licensee_scorecard.csv`, `cso_construction_series.csv`.

### `agents.py` — Multi-Agent System

A governed multi-agent architecture aligned with Opportunity 1 from the literature review. Includes:

- **`ComplianceMonitor`** (working): reads the licensee scorecard, compares recovery rate to the EU 70 % target, returns a structured `AgentResult` with status (`ok` / `needs_review` / `error`), evidence chain, and recommendation.
- **`Forecaster`** (stub): placeholder for ARIMA/Prophet/gradient-boosting forecasts of next-period CDW flows.
- **`ScenarioEvaluator`** (stub): placeholder for what-if policy lever analysis (e.g. landfill levy +€X, mandatory pre-demolition audits).
- **`PolicyRecommender`** (stub): uses Claude to draft policy briefs from upstream agents' findings; requires human approval before any action.
- **`Orchestrator`**: coordinates agents, enforces bounded autonomy (each agent has a declared scope), and maintains a JSONL audit log at `./out/audit_log.jsonl`.

Governance-by-design principles: every agent action is logged with timestamps, inputs, and outputs; the PolicyRecommender's drafts are marked `needs_review` and cannot auto-publish; the Orchestrator appends a governance disclaimer to every output.

## Status

### ✅ Working

- **Data pipeline end-to-end** (`cdw_pipeline.py`): loads, cleans, classifies, and outputs all five EPA years plus the CSO macro series.
- **ComplianceMonitor agent**: fully functional facility-level compliance assessment against the EU 70 % CDW recovery target, with structured evidence and audit logging.
- **Orchestrator + audit trail**: coordinates agents, logs every action, appends governance disclaimers.

### 🔲 Stubbed (To Implement)

- **Forecaster**: needs time-series model (ARIMA / Prophet / gradient-boosting) on `cdw_clean.parquet` grouped by year, material, and/or licensee.
- **ScenarioEvaluator**: needs system-dynamics or econometric model with policy levers (levy rates from `policy_levy_timeline.csv`, EoW decisions from `policy_eow_byproduct_decisions.csv`).
- **PolicyRecommender**: Claude integration code is complete but depends on upstream agents' outputs. Currently only fires when ComplianceMonitor flags `needs_review`.

### ⚠️ Known Limitations

- CSO data ends 2020, EPA starts 2021 — the hand-off year needs care in trend analysis.
- Recovery rate excludes R12/R13 (prep/storage), which is ≈14 % of 2025 tonnage; its final outcome is unknown.
- No design-stage data (BIM, material passports) — upstream/design-phase analysis is out of scope.
- No cost/economic data — Ding et al.-style dynamic modelling needs cost parameters sourced separately.

## How to Run

### Prerequisites

- Python ≥ 3.10
- Install dependencies:

```bash
pip install pandas openpyxl pyarrow anthropic
```

### Step 1 — Run the data pipeline

```bash
python cdw_pipeline.py
```

This loads the EPA and CSO data, computes KPIs, and writes outputs to `./out/`.

### Step 2 — Run the compliance agent

```bash
python agents.py --licensee "Ashgrove Recycling - W0147" --year 2024
```

Replace the licensee name and year as needed. The full list of licensees is in `out/licensee_scorecard.csv`.

### Step 3 (optional) — Generate a draft policy brief

Requires an Anthropic API key:

```bash
# Windows PowerShell
$env:ANTHROPIC_API_KEY = "sk-ant-..."

# Linux / macOS
export ANTHROPIC_API_KEY=sk-ant-...

python agents.py --licensee "Ashgrove Recycling - W0147" --year 2024 --brief
```

The brief is advisory only — it is logged with `status: needs_review` and requires human approval before any action.

### Outputs

All outputs are written to `./out/`. See the [Pipeline Outputs](#pipeline-outputs-out) section for details.
